# Architecture direction

RustHouse is an experimental Rust analytical database. Its long-term goal is
read-only compatibility with a useful subset of ClickHouse MergeTree parts,
followed by a small SQL layer and eventually ingestion.

## Milestones

1. **Part metadata** (this PR): parse modern `count.txt` and `columns.txt`.
   These files describe row count and column names/types, but not the data itself.
2. **Part reader**: decode one supported MergeTree wide part's `.bin` and mark
   files, initially for a small set of uncompressed/fixed-width types. Prove
   correctness with fixtures produced by ClickHouse.
3. **Query integration**: expose decoded batches through Apache Arrow and a
   DataFusion `TableProvider`. Support projection and predicate pushdown where
   correct; measure scans and add pruning incrementally.
4. **Ingestion**: durable single-node append-only writes and recovery.

No replication, distributed query engine, or transparent ClickHouse
compatibility is promised at this stage.

## Safety and compatibility

- The initial CLI only reads files. It never writes into a ClickHouse data
  directory or locks an existing database.
- v1 `columns.txt` parsing preserves the data type *expression* as text; it
  does not type-check or decode any column data.
- `count.txt` is required. Legacy part layouts without it are not supported.
- Checksums, sparse primary-key indexes, compact parts, projection parts,
  serialization variants, and codecs are not interpreted yet.
- Compatibility should be demonstrated against parts generated by ClickHouse,
  not inferred from an incomplete implementation of its storage format.

Reference: [ClickHouse MergeTree source layout](https://github.com/ClickHouse/ClickHouse/blob/master/src/Storages/MergeTree/MergeTreeData.h)
and [NamesAndTypesList serialization](https://github.com/ClickHouse/ClickHouse/blob/master/src/Core/NamesAndTypes.cpp).
